# Modern engine practices (docs state 2026-10-29, Studio 0.745; weekly update 2026-11-02)

Where this file and an older tutorial disagree, this file follows the current docs.

## 1. Code

- **Scheduler:** use `task.spawn` (runs now), `task.defer` (end of this resume point), `task.delay`, `task.wait` (about one Heartbeat). `wait`, `spawn`, `delay` are legacy and slower.
- **Deferred events:** `Workspace.SignalBehavior = Deferred` is recommended and used by template places. Handlers run later, so code like `fire(); return flag` breaks. Re-entrancy limit 10. `Disconnect()` drops pending handlers, `Destroy()` does not. Prefer `signal:Once()`.
- **Script layout:** one `RunContext=Client` Script in ReplicatedStorage, one `RunContext=Server` Script in ServerScriptService, everything else ModuleScripts with a `start()`. Do not put scripts in Workspace; use CollectionService tags. A new Script defaults to `Legacy` RunContext, so set it.
- **Boot and leave order:** create every remote at server start, before any slow map build. A client waiting on a remote that does not exist yet stalls (docs: `WaitForChild` without a timeout yields until the child exists and warns after 5 s; replication order is not guaranteed). Clients wait on a map attribute the server sets when an area is ready (read it, then connect `GetAttributeChangedSignal`), not on load order. `Player.CharacterRemoving` can fire before `Players.PlayerRemoving` when a player leaves (field observation; the reference gives no order), so release per-player state (carried items, seats, locks) through one idempotent function with a per-player flag, called from both events.
- **Content counts (regions, stages, tiers):** use one ordered list of stable string ids, per-domain tables keyed by id, and add a test that every id has an entry in every keyed table. Before raising a count, audit every pin of the old one: parallel arrays sized N, literal indexes (`STAGES[6]`, `stage == 4`), silent clamps (`math.min(i, #T)` reuses the last entry), values derived from the index (seeds, colors), tests that assert N; a missed pin goes wrong at the first entry past the old count. For ids that saves refer to, see `roblox-data-saves` section 4.
- **Types:** use `--!strict` (modes: `--!nocheck`, `--!nonstrict`, `--!strict`; default is `Workspace.LuauTypeCheckMode`). Generics and `typeof()` are supported. Since the week of 2026-09-14 strict mode checks the bodies of generic functions more strictly, so older `--!strict` code can show new errors after a Studio update.
- **Require by path:** `require("./Sibling")`, `"../"`, `"@self/Child"` and `"@game/ReplicatedStorage/Shared/Module"` resolve from the script; they do not wait for replication, so use them for modules that are already there.
- **Parallel Luau:** put code under `Actor`; `task.desynchronize()` / `task.synchronize()` or `Signal:ConnectParallel`; messaging with `Actor:SendMessage` / `BindToMessage`; shared data in `SharedTable`. No `require()` while desynchronized; instance writes need a serial phase; `Terrain:WriteVoxels` is serial-only. Many small actors (64+ is fine); scripts in one actor run serially.
- **Native codegen:** `--!native` or `@native` for numeric and `buffer` loops on the server. Annotate `Vector3` params; avoid `getfenv/setfenv`; breakpoints disable it. Check size with `debug.dumpcodesize()`.
- **Batching:** start `GetProductInfoAsync`, `UserOwnsGamePassAsync`, `GetItemDetailsAsync` calls concurrently with `task.spawn` and they batch.
- **Collision groups:** `PhysicsService` is deprecated and forwards to Workspace. Use `workspace:RegisterCollisionGroup(name)`, `workspace:CollisionGroupSetCollidable(a, b, false)` and `BasePart.CollisionGroup`.
- **Physics:** adaptive timestepping runs at 60/120/240 Hz; use Fixed 240 Hz for racing or tanks. `CollisionFidelity` `PreciseConvexDecomposition` is the most expensive; use `Box` or `Hull`. `Tunable` (new) lets you tune precision per mesh. Raycast max length 15,000 studs.
- **Server Authority (full release 2026-07-09, opt-in):** for competitive or physics-heavy games. `Workspace.AuthorityMode=Server` needs NextGenerationReplication, Input Action System, Deferred signals, fixed simulation and streaming. Gameplay logic runs in functions bound with `RunService:BindToSimulation` and uses `time()` (synchronized), not `tick()`. The full-release post says Backpacks and Tools are supported, but the docs page (updated 2026-11-02) still warns that Tools are not fully supported and that `Humanoid:EquipTool()` / `UnequipTools()` cannot run inside bound functions, so test equip and swap with two clients. Read `create.roblox.com/docs/projects/server-authority` before opting in; combat use is in `roblox-combat-tools`.
- **Still beta (do not ship without a fallback):** script capabilities (`Sandboxed`), `InputActionLabel`, persistent Friends/Global leaderboards (open beta since 2026-08-26, one active board; the post title says "Full Release" but the post and docs say beta), video upload.
- **Collision summaries (Studio-tested 2026-11-01; the public roadmap still lists them for early 2027, so confirm in a published test place before relying on them live):** `part:BindToCollisionSummaries(function(summaries) ... end)` returns an `RBXScriptConnection`; once per frame after the physics step it passes every contact of that part (`Time`, `Part0`, `Part1`, `Point`, `Normal`, `RelativeVelocity`, `Area`). Use it for impact sparks, sounds and hit location instead of `Touched` plus velocity guesses. Impact speed = `s.RelativeVelocity:Dot(s.Normal)` (positive on a hit); a landing part also reports follow-up rebound contacts in the next frames, so filter by a speed threshold. Do not call it inside a `Touched` handler.
- **Animation Graph Editor (full release 2026-07, DevForum staff post):** node-based blend trees and animation logic built in Studio that run in live games (`create.roblox.com/docs/animation/graph-editor`). The Luau-expression state machines below are still beta.
- **Luau betas (Studio Beta Features, do not ship):** `if local x = expr then` and `if const` (also as expressions, narrows types), and State Machines with Luau Expressions for animation graphs.
- `Player.UserId` is still the global id; `Player.User` exists but scoped ids have not rolled out.

## 2. UI

- **Style first:** pick the UI style from the four basic cards in `roblox-game-pipeline/assets/ui-styles/` (`roblox-game-pipeline` section 3, step 4, with a free Studio mockup; README has build notes and phone risks per style); stud chunky goes to `roblox-ui-genre-studs`, sci-fi and military looks to `roblox-ui-genre-scifi`.
- **Icons:** icons come from the Creator Store by default (one icon pack, `roblox-store-art-pack` section 4); generated icons are an option only when the user asks. Never build an icon from Frames, lines, `Path2D`, parts or emoji, such as a house from a triangle and a box or an arrow from rotated bars: they come out crude (owner rule, 2026-11-08).
- **Layers, not flat boxes:** a panel or button built from one Frame, one color and a default font reads as 2015-era UI. Current hits stack 3-5 layers per element: 9-slice or sprite art, a gradient, a stroke, a shadow or glow, and an icon (judgment from 2026 artist posts and top-game stills).
- **Conventions players already know** (docs, UI and UX design): an X button closes a dialog, grey means unusable, a lock icon means not yet unlocked. The docs' consistency example: close buttons always square, red, with a white X, only at the top right of a dialog; a price the player cannot afford shows in red. Keep one color per meaning across text, icons and bars.
- **Layouts:** `UIListLayout` has flex (`HorizontalFlex`/`VerticalFlex`, `ItemLineAlignment`, `UIFlexItem.FlexMode` Fill/Grow/Shrink/Custom; slightly more expensive). Also `UIGridLayout`, `UITableLayout`, `UIPageLayout`. A `UIAspectRatioConstraint` or `UISizeConstraint` overrides layout sizing. `AutomaticSize` turns `Size` into a minimum. To reverse order negate `LayoutOrder`.
- **Styling system:** `StyleSheet` (tokens as `$Token` attributes, themes), `StyleRule` selectors (class, `.tag`, name, GuiState, `@query`), `StyleLink` on a ScreenGui (one sheet per tree), `StyleDerive`. Built-in queries `@ViewportDisplaySizeSmall/Medium/Large` (phone and tablet = Small, laptop = Medium, console = Large) and `@PreferredInputTouch`. Use it for per-device scale instead of hand-written branching.
- **Effects:** `UIShadow` and per-corner `UICorner` radii (full release 2026-06-23), `UIGradient` Radial/Elliptical/Conical plus `Scale` and `TileMode` Repeat or Mirror for repeated patterns such as stripes and bar segments (full release 2026-10-29; recipes in `roblox-ui-genre-scifi`), 9-slice via `ScaleType=Slice` + `SliceCenter`. Upgraded `UIShadow` (text, inset, knockout) is still Studio beta: without it, `Mode = Text` draws a box over the whole label instead of a glyph shadow (Studio 0.746, 2026-11-05), so give text a `UIStroke` or an offset copy of the label as its shadow. `RichText=true` for markup (localisation strips tags). Prefer these modifiers and `StyleSheet` tokens over shadows and gradients baked into images for anything that is not illustrative art: they follow `UIScale`, themes and device rules and cost no texture memory (judgment). `UIGradient` (docs): at most 6 color stops, none on an object with a text stroke (`TextStrokeColor3`), and animate `Offset` or `Rotation` instead of setting `Color` or `Transparency` often, which rebuilds the sequence. A `UIGradient` multiplies the parent's color (Studio 0.746; the docs only say "blended"): give a gradient face a white `BackgroundColor3` and put the real colors in the gradient, or the face comes out darker.
- **CanvasGroup:** fades or tints a whole panel as one texture (`GroupTransparency`, `GroupColor3`). It costs extra texture memory, renders blank when the client's memory cap is exceeded, wants a static size and needs `ZIndexBehavior` Sibling (docs). A ScreenGui made with `Instance.new` starts as Global, and there a CanvasGroup ignored `GroupTransparency` and drew opaque (tested 2026-11-08, Studio 0.746). Use one per panel for open and close fades, never one per button; pops use `UIScale`. Rounded clipping (`UICorner` on the clipping frame) still needs a CanvasGroup (DevForum 4737864).
- **Player settings:** multiply each `BackgroundTransparency` by `GuiService.PreferredTransparency` and react to its change (docs; 0 means the player wants opaque backgrounds). Honor `PreferredTextSize` (`roblox-ui-typography` section 3) and `ReducedMotionEnabled`: swap moves, pops and loops for a short fade and drop flashes (judgment; flash limit in `roblox-fun-effects` section 10).
- **Rotated clipping:** a `ClipsDescendants` parent clips rotated children and `Path2D` too (default since 2026-09-24). `StarterGui.ClipsDescendantsSupportsRotation` no longer exists in Studio 0.746 (2026-11-08), so the opt-out is gone. Check spinning icons, rays and tilted cards inside clipped frames; fix with `ClipsDescendants=false` or a `CanvasGroup`. Cut-corner panels use this (`roblox-ui-genre-scifi` section 2).
- **Click-through:** `GuiObject.InputSink` (None, Activate, All; buttons default to Activate) decides whether UI swallows clicks meant for a `ClickDetector` or `DragDetector` behind it.
- **Safe area:** `ScreenGui.ScreenInsets` defaults to `CoreUISafeInsets`, which already clears the top bar and cutouts. Add manual insets only with `None`/`DeviceSafeInsets` or `IgnoreGuiInset`. Where things go per device, Roblox's reserved zones in px, size floors and a device check script: `roblox-ui-layout`.
- **SurfaceGui/BillboardGui buttons** work only when parented under `PlayerGui` (use StarterGui); a SurfaceGui button also needs the part's `CanQuery=true`.
- **Input:** prefer the Input Action System (full release 2026-06-11; `InputContext`, `InputAction`, `InputBinding`; set `Workspace.PlayerScriptsUseInputActionSystem`) with one binding each for gamepad, keyboard/mouse and touch. The converted player scripts roll out in three phases (dates announced later): do not depend on legacy `PlayerModule` internals such as `GetControls()`; for fully custom controls set `StarterPlayer.CreateDefaultPlayerModule` to false. Use `UserInputService.PreferredInput`, not `TouchEnabled` (true on touch laptops). Show per-device hints with `InputActionLabel` or `GetImageForKeyCode`.
- **Movement abilities** (sprint, double jump, dash, wall moves): check the Character Controller Library (`create.roblox.com/docs/characters/character-controller-library`, beta via File > Beta Features) before hand-rolling a controller.
- **Mobile:** the docs disagree on the default orientation (the `StarterGui.ScreenOrientation` reference says `Sensor`, landscape or portrait; the mobile input guide and the `PlayerGui.ScreenOrientation` reference say landscape, `LandscapeSensor`), so read `StarterGui.ScreenOrientation` in the place instead of assuming landscape, and test each orientation it allows. Keep UI out of the default thumb zones and relative to the jump button; `UITextSizeConstraint.MinTextSize` not below 9. 75 percent scale looks huge on a 4K TV, so adapt with display-size queries. Test with the Device Simulator and the Controller Emulator, but check memory on real devices.
- **Fonts:** `Gotham`, `GothamMedium`, `GothamBold` and `GothamBlack` are removed and map to Montserrat; `Arial` and `ArialBold` map to Arimo. Fonts cannot be uploaded. Choosing fonts, readability and non-Latin coverage: `roblox-ui-typography`.
- **UI review before done:** (1) open every panel and tab by clicking its HUD button with real input (`user_mouse_input`, `roblox-studio-ai-tools` section 2), not by calling the open function or setting `Visible`, at a desktop size and a phone size in each orientation the place allows; look for a panel sitting low or off-centre. (2) Overlap audit with a dev-only snippet: per group (HUD, open panel, toast, popup) list the `AbsolutePosition` and `AbsoluteSize` of every visible `GuiObject`, then report intersections between groups and every `TextLabel` or `TextButton` whose `TextFits` is false; cover the idle HUD, each panel and tab, and a toast over a panel; fix to zero or list each exception. (3) Read the console afterwards: panel code errors show only at runtime. (4) Look check: put the chosen mockup or reference frame beside our screen at the same viewport size, list the gap per element (shape, fill, edge, color, font, icon, spacing, density), fix or record each, and get the user's look verdict. Steps 1-3 show the UI works, not that it looks right; one UI lane reported done on green checks and was rejected on sight (field note, 2026-11-08).
- **Panel loading and scroll cue:** prebuild panels hidden after join and preload their images in the background (`ContentProvider:PreloadAsync`, `roblox-store-art-pack` section 7); set `Visible` only once the layout is final, so images do not pop in and a grid does not re-flow on first open. Size a scrolling panel so the next row peeks out as a scroll cue. `ScrollingFrame.CanvasPosition` is in screen px after any ancestor `UIScale`, like `AbsolutePosition` (Studio 0.746): to scroll to an item, add `item.AbsolutePosition.Y - scroller.AbsolutePosition.Y` to `CanvasPosition.Y`.

## 3. World, streaming, memory

- `StreamingEnabled` is on for new places. Recommended: `ModelStreamingBehavior=Improved`, `StreamingIntegrityMode=PauseOutsideLoadedArea`, `StreamOutBehavior=Opportunistic`, `PredictiveStreamingMode=Enabled`, `EnableSLIMAvatars`. `StreamingMinRadius` 64 and `StreamingTargetRadius` 1024 are defaults. Set `Model.LevelOfDetail=SLIM` on static models (keep each under about 64 cubic studs). Persistent models are rare; wait for `Workspace.PersistentLoaded`.
- **Client-created parts do not stream out** (docs: instances created or cloned by client scripts are exempt from streaming out unless parented under a server-created instance), so a client-built map only grows until your script removes parts. Budget it with a build window: build the areas near the camera, not everything at once.
- **Render reach (field observation, one scene):** at low graphics quality, phones included, parts beyond about 400-450 studs were not drawn; the streaming docs give no number. Since 2026-11-05 the lowest quality level draws at least 500 studs (was 200) and the next automatic levels reach 800, 1200 and 1600 (DevForum; Roblox says not to design around exact numbers), so that observation predates the change: recheck in the Performance Simulator (status board). Keep hero scenery such as landmarks or a skyline within about 380 studs of the camera path, and put an opaque probe part at that distance before debugging materials (if it vanishes too, it is draw distance). `Lighting.PrioritizeLightingQuality` (`roblox-feel-audio-vfx` section 4) may shift the cut-off; untested. Reproduce in the client: Settings > Graphics Mode > Manual, then lower the quality.
- **Place clones by pivot, not by bounding box:** set the pivot at the feet once (`BasePart.PivotOffset` on the `PrimaryPart`, or `Model.WorldPivot` without one) and place with `PivotTo`. `GetBoundingBox` of a template that has not simulated gave a wrong first placement (field observation). A fallback model must match the real one's pose, scale and pivot so the swap does not jump. Preload before the first show (`roblox-store-art-pack` section 7) and test the cold path after a fresh server start.
- Budgets: frame 16.67 ms at 60 FPS. Server memory is 6.25 GiB + 100 MiB per peak player; stay under 50 percent. Client crash rate above 2-3 percent needs investigation. About 65 percent of a typical game's players are on Android, mostly 2-8 GB RAM; test on a low-end device (Infinix Smart 9, Moto G05, Oppo A18, Fire HD 10) for 10-15 minutes. Example target from the docs: under 1,000 draw calls and 1,000,000 triangles (measure your own baseline).
- Textures: memory grows with resolution (1024 is 4x a 512). Most images at most 512; minor ones under 256. File size does not change memory.
- Same MeshId + same texture = one draw call. Never import a whole map as one file; use packages; tint with `SurfaceAppearance.Color` (only on SAs baked in a Studio-saved place: `roblox-pitfalls` section 4).
- Keep ReplicatedStorage lean; large content in ServerStorage. Tween on the client, never the server. NPCs: disable unneeded Humanoid states, use `AnimationController` for static NPCs, pool them. Avatar Joint Upgrade (Phase 2 rolling out since 2026-05-27, forced Phase 3 targeted for the end of 2026): R15 joints move from `Motor6D` to `AnimationConstraint`, so code that finds joints with `IsA("Motor6D")` or writes `Motor6D.Transform` breaks. Read the `AnimationConstraint` page ("Migrating from Motor6D"); `StarterPlayer.AvatarJointUpgrade` = Disabled is only a temporary opt-out.
- Particles: 400 per second (100 on mobile), lifetime max 20 s. Highlights: cap 255, first costs up to 1 ms on mobile. Shadows are off below quality level 4.
- Tools: MicroProfiler (Ctrl+Alt+F6 on device), Developer Console (F9), Shift+F2/F3/F5 stats, `debug.profilebegin/profileend`, Assistant skills `rbx-perf-profiling` and `rbx-scene-analysis`. `Workspace.PlayerCharacterDestroyBehavior` destroys old Player and Character objects and becomes the default on 2026-11-11 (status board). `DataModel.ServerLowMemoryWarning` lets server scripts free memory before an out-of-memory crash (status board).

## 4. Security checklist for every remote and prompt

1. Context: is the player alive, close enough, allowed?
2. Type: `typeof(x) == "Instance"` and `IsDescendantOf` the expected container (tables can pose as Instances).
3. Value: `math.isfinite` (reject NaN/inf), range-check numbers, cap string length and table size, `utf8.len`.
4. Rate-limit with a token bucket or cooldown per player.
5. `ProximityPrompt`, `ClickDetector` and `DragDetector` events can be fired by exploiters from any distance; only `Triggered` has a server distance check, so verify distance yourself. Give the check movement slack (about walk speed x ping, 3 studs at 16 studs/s, judgment), and never let the client show an action button farther out than the server accepts: a Buy button shown at reach + 4 met a server that took reach, and the player got "walk closer" (field note, 2026-11-09).
6. Purchases: grant in `ProcessReceipt`; never trust `PromptProductPurchaseFinished`.
7. Unanchored parts are exploitable through network ownership; anchor them or set the owner.
8. Remotes cannot pass functions; metatables are stripped; `UnreliableRemoteEvent` drops payloads over 1,000 bytes.
9. Teleports: use server `TeleportAsync` (client `Teleport` is deprecated), set Access Control for Places to "Secure within universe only", treat teleport data as client-visible. For private servers set `TeleportOptions.ReservedServerId` or `TeleportOptions.VipServerId` (a GUID, `game.PrivateServerId` of the target); set at most one, since two raise a Luau error. The old access-code fields still work but print deprecation messages. Handle `TeleportInitFailed`: players can close or leave VIP servers.
10. `Player.DeviceTrustLevel` (Pending/Unknown/None/Standard/Full) is a server-side signal and always Pending in Studio. Device Trust API (announced 2026-10-27, Android and the upcoming Web client; iOS, console and Windows planned for 2027): set `IntegrityService.EvaluatePlayerDeviceTrust` on the server to approve or reject a join (return a decision table, with a kick message), or read the cached level later. Never trust the value on the client; have the server tell the client which features are on. It does not replace server-side validation.
11. Buffer networking libraries (Zap, Blink) cut bandwidth but do not replace steps 1-4. Start with plain `RemoteEvent` and `UnreliableRemoteEvent`; switch only when the profiler shows remote cost.
12. One purchase path per action: a server `ProximityPrompt.Triggered` handler next to a client buy remote charged twice for one press. Keep one.
13. Server-timed flows: when the server decides a result at request time and the client then plays a long presentation (cinematic, reveal), a script can skip the presentation and request again at once. Store `readyAt = now + 0.8 x minimum presentation time` on the server (the 0.8 is slack for latency), refuse earlier requests, and cap any storage such farming would fill.
14. Client-reported timing (a meter stopped on PERFECT, a rhythm hit) is a claim. The server knows when the meter started and its speed, so it checks the phase within a latency margin.
15. Close server sessions on every exit path: a per-player flag (launching, rolling, in a minigame) is cleared on finish, death, cancel and leave; a timeout is only the backstop. A player who died mid-flow stayed locked until a 40 s timeout.

Items 12-15 are field observations from one prototype (2026-11-04): an independent code review found all four while lint, types and 296 tests were green. Review remote flows on their own; tests do not cover them.

### 4b. Server-side detection (beyond single remotes)

Source: `create.roblox.com/docs/scripting/security/server-side-detection` and the other pages under `scripting/security`. Client-side anti-cheat is bypassable; the server decides.

1. **Neutralize first, punish rarely:** rubber-band a speed-hacker to the last valid position instead of kicking; log every flag with the player, values and time.
2. **Movement checks:** compare distance moved per interval against the allowed speed plus a margin for lag; check impossible teleports and noclip through walls the player could not pass.
3. **Heuristics:** flag progress that is possible but improbable (a 5 s obby run when the record is 30 s, a day of currency in a minute). Review flags before banning; false positives on laggy phones are common.
4. **Economy:** recompute rewards on the server from server state; never accept amounts from the client (`roblox-data-saves` for saves, `roblox-combat-tools` for damage).
5. **Backdoors:** free models can hide `require(<id>)`, `loadstring` or `getfenv` calls that hand control to an outsider. Quarantine and search every inserted model (`roblox-store-art-pack` section 3); keep `LoadStringEnabled` off.
6. **Player text:** any text one player writes that others see (pet names, signs, notes) goes through `TextService:FilterStringAsync` before display, and section 5 decides whether it may exist at all.

## 5. Chat, voice, platform

- Platform-integrated chat (`TextChatService.PlatformIntegratedChat`, Studio-only toggle) becomes **required for all games in May 2027**; in Phase 2 (February 2027) all games are opted in automatically with a temporary opt-out (DevForum 2026-10-21). When on, `TextChatMessage.Text`/`Translation` return empty, and `PrefixText`, `OnIncomingMessage` and `Player.Chatted` are unsupported. Move to `TextChannelWindow` and `TextChatCommand` now. Games with the default chat and no customization need no action.
- **Free text is enforced now (DevForum 2026-10-20, phase 0):** any player-to-player free text outside `TextChatService` (signs, bulletin boards, pet names, license plates, trading notes, announcement systems, admin-tool messaging, comment systems) must be removed, moved to a `TextChannel`, or rate limited to 1 update per minute. Violations get notices and can lead to suspension; developers report games taken down for weeks, so audit this before every release.
- **Chat roadmap (official, 2026-10-22):** `TextChannelWindow` (also in a `SurfaceGui`) and `ChatWindowConfiguration.TextChannelDisplayMode` are live per the announcement (the property is not in the engine reference yet on 2026-11-03: look it up before using it); `TextSource.CanSend=false` makes a channel read-only; `DisplaySystemMessage` is client-side, so call it per player from the server (rich text works). Display-name colors and gradients: November 2026. Role badges replacing prefixes plus keyword commands anywhere in a message: February 2027. Quick Action Menu: April 2027. Creator blocked-word list: May 2027. Bubble chat styling stays (`BubbleChatConfiguration`, `OnBubbleAdded`). Multiple channels in one window are not supported yet (use one window per channel or the default window).
- **Avatars:** `AvatarUnificationMode` has a planned deprecation (announced for 2026-12-01 in a DevForum recap; the engine reference does not mark it yet on 2026-11-03), so do not build on it. SLIM avatars use `Workspace.EnableSLIMAvatars`.
- Voice chat: experiences up to 100 players, ID-verified 13+ users in supported countries. Cross-server chat about 200 users per channel.
- Matchmaking: up to 5 server attributes and 5 player attributes per game.
- Audio import: under 20 MB, under 7 minutes, 48 kHz or less; free imports per 30 days 2,000 (ID verified) or 100 (unverified).
- Data/Memory/HTTP limits: see `roblox-studio-ai-tools` and the Open Cloud numbers in `roblox-pitfalls` section 1; DataStore value 4 MB, keys 50 characters, 25 MB/min read and 4 MB/min write per key.
