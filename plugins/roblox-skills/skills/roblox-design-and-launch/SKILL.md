# Design, policy and launch

Read from the official creator-docs repository (state 2026-10-29). Numbers and policies change; the checks in section 8 say when to re-read the live page. Pair with `roblox-dev-workflow` and `roblox-store-art-pack` (icon and thumbnail craft).

## 1. Design

- **Core loop** = minute-to-minute interaction + most repeated action + progression engine. Write all three before building. A game without a progression engine feels shallow.
- **Prototype** with paper first (systems, UI flows, economy), then a greybox in Studio (feel, camera, controls). Paper gives speed and finds design flaws early, but cannot test feel and can give false positives; a greybox does.
- **Onboarding (first-time user experience):** teach the essentials, reach fun quickly, leave players wanting more. Measure the player funnel step by step and fix the biggest drop-off with an experiment. Player-facing instructions may be fewer than the funnel steps; keep the funnel step numbers and names unchanged so old and new data compare. Check that each step's reward covers what the next instruction asks for. Hide goal text after a short time (15 s in one game after a player complaint, 2026-11), keep the world guide (arrows), and show the text again when the step changes. Where there is no guide (a run, an arena), the text names the way out ("Press Exit, then ...") or players stall.
- **UI/UX:** prioritise information (what is the player doing right now?), keep visual language consistent, follow platform conventions. Design for phone first, then scale up. Test layouts with Experiments, toggle platform or seasonal UI with Configs.
- **Economy:** every currency needs sources, sinks and a pacing target. Every stat or currency the player sees also needs a written answer to "what raises it" and "what is it for"; with no answer, cut it or give it a use. After removing a feature, grep for the currencies or stats it left with no use. Simulate the economy in a spreadsheet or Lune script before shipping prices (rules below). Avoid power that only paying players can reach if the game is for younger audiences.
- **Economy sim rules** (field observations):
  - In a tiered economy (price grows per tier, each tier adds a gain), retune price growth and per-tier gain together in the sim: cutting only the price lets progress run away. Live price tests (section 5) still change one thing at a time.
  - Run one bot policy per way to play: the intended path plus every shortcut (for example repeating one action, standing idle, camping in one spot), and assert that each shortcut earns less than the intended path. The intended-path bot must buy every item on the path; a sim that skips an item hides gate failures. Add a policy whenever you add a shortcut.
  - Run the sim to the end state before adding content: a stall near the end shows only there.
  - A gain that grows with the stat it raises (gain = base + a percent of current power) compounds: in one prototype an idle bot reached the top tier in about 5 min. `base * sqrt(1 + power * k)` stretched that to about 30 min (field observation, 2026-11-04). Assert a time-to-top for the idle policy.
- **Genre craft:** for chunky simulator/tycoon looks use `roblox-ui-genre-studs`; for other genres use the UI rules in `roblox-engine-2026`. Weapons and damage: `roblox-combat-tools`; rounds, lobbies and teams: `roblox-match-flow`. Judge the idea against the live market (trends, keywords, competitors) with `roblox-market-research`.
- **Quests, daily rewards, season pass:** start from Roblox's official feature packages (missions, season passes, bundles, engagement rewards; docs `resources/feature-packages`) before hand-rolling one. Badges mark milestones; their award counts later show how far players get.

## 1a. Platform play patterns (advise from these in planning)

Use this when a plan is being shaped. Compare the plan with the table, then give the developer at most 3 concrete suggestions in the form "pattern -> your plan -> change". Evidence grades: **O** = Roblox docs, **M** = measured by us on the live charts (n=76, 2026-11-02, approximate), **V** = vendor report (GameAnalytics, sample = 500+ games with 1M+ MAU, Aug 2025-Jul 2026; not Roblox's own data), **J** = our design judgment from the evidence above it.

| Pattern | Evidence | Planning advice (J) |
|---|---|---|
| Players come for variety, low friction and social play; a session is a handful of games, and players join one briefly and switch (YouTube-like) | O (`roblox-user-base`) | Value must show before the player's patience runs out. Do not require a tutorial, queue or signup before the first reward |
| Median player opens games 3 times a day; median player session 7.3 min; median game session 9.8 min (top 5% of games 16.6 min) | V | Plan a complete mini-loop (action, reward, upgrade) in 5-10 min. Save progress at any moment. Make leaving and coming back painless |
| Median D1 10.3%, D7 1.6%, D30 0.5%. p25: 8.4 / 1.0 / 0.3%. Top 1% of games: 22.2 / 9.1 / 4.7%. GameAnalytics calls the often-quoted 20% D1 benchmark inflated | V | Set targets from this table, not from blog posts (genre D1 targets on blogs, such as "obby 25-35%", give no method: do not use them). Compare with your own Creator Hub benchmark (Similar experiences / Genre). D1 is won in the first two minutes; D30 needs live ops, events or deep progression |
| Friends are a main growth channel (invite, join friend, word of mouth). Third-party guides claim friend play multiplies return rates several times, but give no Roblox source | O for the channel; the multiplier is unverified, do not quote it | Social is a **bonus layer**, not a prerequisite. Add join-friend-friendly hooks (see below) |
| No source gives a solo versus social share of playtime. Charts show both: about 18% of sampled descriptions mention co-op or friends words and 4% mention solo (keyword count, rough) | M | Design **solo-viable, better with friends**: the core loop must work with one player in the server |
| Max players on the charts: median 16; 9 of 76 games cap at 1-6, 23 at 7-12, 36 at 13-30, 8 above 30. Weighted by current players: 5% / 51% / 30% / 14% | M | A cap of 7-12 carries about half of all current players in the sample; a cap of 1-6 is rare. Choose the cap from the design (see below) |
| Devices (GameAnalytics, all devices a player used in a year): 44% both phone and PC, 40.8% PC only, 11.6% phone only, 0.4% console only. Newzoo counted 24% phone only (different method, excludes the youngest) | V | Plan for phone and PC from day one, controls and UI included. Console is a small extra |
| Genre session lengths (ROLearn, Q4 2025-Feb 2026): roleplay 48 min against simulator 26 min; co-op horror and roleplay lead long sessions | V, one source | Genre sets the session you can expect. Do not plan a 60-minute loop for a simulator |
| Games strong in both retention and monetization "might receive broader distribution"; fix retention first, then monetization raises Home impressions (`discovery-faq`). RFY "intentionally provides more impressions for highly retentive games at the expense of near term monetization" (Q2 2026 letter); RFY weights long-term retention and age cohorts (Q3 2026 letter) | O | Fix retention before tuning spend. Track both together; do not plan around one strong number |
| Hits decay fast: measured and tracked peaks fall to a small fraction within months (examples and the `history` command in `roblox-market-research` section 6) | M, V | Size servers, economy and live ops for the week-8 audience, not the launch peak. Have D8-28 hooks and weekly drops ready before launch |
| Platform, Q3 2026: 138M DAU; bookings 1.7B USD (-12% year over year); 18+ is 29% of age-checked DAU (37% in the US); about 40% of the weekly RFY top 100 by impressions were created in the last 3 months; Roblox reports games "created almost entirely with AI" reaching the top 20 | O (Q3 2026 letter) | Plan revenue conservatively. A 16+ idea is not niche. New games break in on retention, and speed alone is not a moat: name one thing the game does that the top clone does not (twist test) |
| About 3.8% of players spend anything in a year; median payer spends $0.81 a year, top 10% $8.88 | V | Monetization must be useful to the 96% who never pay; free play stays complete |

**Solo-viable checklist (check at planning time):**
1. Can one player finish the core loop alone, in an empty server? If not, name the fallback: bots or NPC allies (`roblox-bots-npcs` section 5), a smaller mode, or a short wait with a bot fill.
2. Is the minimum players to start 1 for the main mode? If a match needs more, set a timeout that starts with bots.
3. Does progress come from solo actions, with group actions as a multiplier (bonus XP, shared base, co-op boss, trading)?
4. Is there a reason to bring a friend: friend bonus, invite prompt (`SocialService:PromptGameInvite`, docs `production/promotion/invite-prompts`), joining next to friends (official Spawn With Friends module, docs `resources/modules/spawn-with-friends`), shared plot, leaderboard among friends, free private server for the group (`private-servers`; under-13 players may be blocked from them by parental settings)? Friend features must also work with zero friends: since 2026-09-30 the friends-list APIs (`Players:GetFriendsAsync` and related) return empty by default for Australian users under 16 (O), so never gate progress on friend count.
5. Does the join-friend path work for a server that is full, private or reserved (`TeleportOptions` ids)?
6. Is anything that needs a crowd (trading, shops of other players, PvP) labeled as optional so an empty server does not look dead?

**Max players guidance (J, from the table):** solo-first or heavy per-player world (tycoon, base-building, obby with checkpoints): 7-12 keeps the world lively and cheaper. Social hubs, roleplay, battle games: 16-30 and up when the map and `StreamingEnabled` can carry it. Under 7 only for a deliberate co-op or horror format. Justify values outside 7-30 (`roblox-launch-benchmarks` gate 9). Per-player plot games (tycoon, garden, base): set `MaxPlayers` to the plot count, and hand plots out from a waiting list, not only at join; in one prototype a player who joined while all plots were taken never got one, even after someone left (field observation, 2026-11-04).

Re-measure the M rows with the `roblox-launch-benchmarks` scripts before quoting them after a month; re-read the V sources for new reports. For today's charts, keyword competition, competitor teardowns and decay curves, run `roblox-market-research`.

## 2. Monetization options (Robux)

| Option | What it is | Notes |
|---|---|---|
| Game pass | One-time purchase, benefit forever | Good for access and permanent perks. Icon up to 512x512. Cross-game pass and product sales ended 2026-05-30 |
| Developer product | Repeatable purchase | Currency packs, consumables; grant on the server after `ProcessReceipt` succeeds |
| Subscription | Recurring monthly benefit | Auto-renewing; Robux price at least 49 or local-currency tiers (2.99/4.99/7.99/9.99/14.99 USD); payout always in Robux (Robux subscriptions pay 70 percent monthly; local-currency ones 70 percent in month 1, then 100 percent); max 50 per game; Robux regional pricing cannot be turned off; Robux price changes allowed once per 60 days with 30 days' notice |
| Paid access / private servers | Pay to enter, pay for a private server | Roblox Plus subscribers get paid private servers free and you are still paid for their time |
| Immersive ads | Roblox serves ads in your 3D space | Billboards (video up to 30 s, or image) and portal ads; AdGui between 8x4.5 and 32x18 studs. Needs 13+, ID-verified, 2FA, approved questionnaire and 2,000 monthly unique visitors; paid on the 25th of the next month. Hide ads where `PolicyService` says ads are not allowed |
| Rewarded video | Player watches a 6-30 s ad for a reward | Needs 13+, ID-verified, 2,000 monthly unique visitors. The reward must be a developer product, never Robux (suggested value 3-10 Robux). Use `AdService` and check `GetAdAvailabilityNowAsync`; keep it optional |
| Avatar items / Marketplace | UGC items sold to players | Separate creator requirements |
| Creator Rewards | Robux for Daily Engagement and Audience Expansion | Replaced Engagement-Based Payouts on 2025-07-24. Daily Engagement: 5 Robux per Active Spender per day who plays 10+ minutes in one of your first 3 experiences that day (Active Spender = at least 9.99 USD of qualifying purchases in 60 days). Audience Expansion: 35 percent of the first 100 USD a new or returning user spends in 60 days; needs 100+ average DAU. Earned Robux with a 60-day hold |
| Roblox Plus | Subscribers get 10-20 percent discounts (Roblox covers it, your earnings are not reduced) | You can earn for driving Plus sign-ups (up to 750 Robux each) and paid private server time (up to 100 Robux per subscriber per month). **Never hard-code prices in shop UI:** a Plus subscriber would see the wrong price. Read `MarketplaceService:GetProductInfoAsync` (`PriceInRobux` = what this player pays, `UserBasePriceInRobux` = original) or `GetDeveloperProductsAsync` |
| Robux transfers | Player sends 10-500 Robux through `PromptRobuxTransferAsync` | The game earns 10 percent (DevEx-eligible); the sender must be a Plus subscriber (docs `robux-transfers`) |
| Sponsored ads (Ads Manager) | You pay to promote your game | Goals: Plays, Earnings (ROAS, counts Creator Rewards, ads and product revenue) and Engagement. Up to 25 image creatives per campaign (the campaign panel shows 0/25, 2026-11-05; the docs still say 10) are shown evenly, a built-in creative test. Ads do not change RFY rank. More than 70 percent of the top 100 games run sponsored ads (Q3 2026 earnings call, read via a third-party transcript). Sponsored tiles now also reach users 13 and under (DevForum Ads Manager recap, 2026-10-02) |

Sponsored campaign setup (one game's first campaign, 2026-11-05; "seen" = in the Ads Manager UI, "docs" = `production/promotion/ads-manager`):

- **Account:** the Ads Manager account belongs to the group that owns the game, and the time zone picked at creation applies to every date and time (seen). A card needs an 18+ account and takes a temporary 1 USD hold (docs).
- **Objective:** Engagement (beta, aims at the Kids & Select reach threshold) locks the audience to All players and closes advanced targeting; Plays keeps targeting; Earnings can show "coming soon" (seen). The Recent audience needs 10,000+ recent players, Lapsed 20,000+ (docs).
- **Budget:** the payment method cannot change after publishing (docs). "Run continuously" and auto-reload are both on by default, so nothing caps the spend: for a test set an end date, which makes days x daily budget the maximum (seen).
- **Creatives:** upload them to the asset library early (up to 10 files at a time, moderation usually within 48 h, docs); a campaign stays "Scheduled" until its review passes, which takes about 24 h (docs, seen). Images show at 16:9; keep key text off the bottom edge. AI generate (beta) makes 3 variations at 1344x756 per run against a "100/100" run counter and takes reference images only by asset library id (an image id uploaded through Open Cloud errors). In one test it added the game title by itself, ignored text asked for in the prompt, letterboxed one variation and drew an arrow backwards: use it for drafts and check every image (seen).
- **Join options:** the start place defaults to the root place. Launch data needs `Player:GetJoinData().LaunchData` handling in the game and is visible in the join URL, so players can share it; leave it empty without that code (docs, seen).
- **After launch:** the first 24 h show as "Learning" (docs; staff posts say 24-48 h); pausing or big edits restart learning (staff), so leave the campaign alone. Report data can lag up to 48 h (docs).

Other rules: **paid random items** include probability modifiers (luck boosts such as "2x Luck" passes, pity systems, rate-up items, enhanced drops). Odds must be numeric, sum to exactly 100 percent, show before the spend and update while a boost is active; a long list may sit behind a button labelled "Info" or "Details" (a bare (i) icon does not qualify). Build the odds UI from the same table that rolls. The rules also cover indirect purchases (keys, reroll tokens or spin tickets bought with Robux or paid currency); free random rewards earned by play need no odds. Check `PolicyService:GetPolicyInfoForPlayerAsync` (`ArePaidRandomItemsRestricted`) and give restricted players one of the docs' treatments: a free earnable path, a fixed order disclosed before purchase, direct purchase priced on expected value, hiding the item, blocking with a message, or keeping them out of that area. When `IsPaidItemTradingAllowed` is false, the player cannot trade paid items or their outcomes (docs `paid-random-items`). Reveal and rarity design: `roblox-fun-effects`. Fake urgency timers and always-on "sales" are banned; paid access costs 25-1000 Robux (or local-currency tiers) and excludes private servers; developer product price 1 to 1 billion Robux; managed regional pricing runs 30-100 percent of the default and is on by default for new passes and products.

Items outside the game: listed passes and developer products also appear on the game page, Home, search and after a Robux purchase, and Roblox may fund discounts on them (your earnings unchanged). A developer product bought there still grants through `ProcessReceipt`, which Roblox checks (Creator Hub shows a banner for a broken handler). Decide list or unlist per product; the global Shop button is off by default (O, DevForum 2026-09-22). To unlist a developer product, PATCH multipart `storePageEnabled=false` (204; deprecated in the spec, and GET did not return it in a 2026-11 run, so check the live game page). Game passes have no such field. Unlist developer products that sell random outcomes: a restricted player (`ArePaidRandomItemsRestricted`) can buy them on the game page, outside your in-game check, and a receipt cannot be declined (`NotProcessedYet` leaves it unresolved, and unresolved purchases are not refunded; docs `ProcessReceipt`). In `ProcessReceipt`, grant a restricted buyer a non-random item of the same value. A luck pass cannot be unlisted: for restricted players it has no effect and shows as unavailable (one game's handling, 2026-11). Refunds and chargebacks: Roblox revokes passes but not developer products. Add the Transaction Refunded webhook (`roblox-release-automation` section 1) and revoke granted goods yourself; the payload amount is the original price.

Coming, not shipped (announced at RDC 2026-09-11 and the fall roadmap; verify live before planning around them): skippable pre-roll video ads (Plus subscribers exempt), developer push notifications and pass free trials, passes shown on Home before entry, offline solo play (mid 2027).

Design rules: never block the core loop behind a purchase; do not give Premium or paying players an unfair tactical edge; describe offers honestly in the description (no number an upgrade or update can make false, such as a per-second rate; re-read pass and product text after a balance change); do not promise Robux or out-of-game rewards. Add monetization after the core loop is fun, with funnel and economy events logged from the first build.

**DevEx (cashing out):** only Earned Robux counts. Standard rate 0.0038 USD per Earned Robux (30,000 Robux = 114 USD); balances earned before 2025-09-05 10:00 PT cash out at 0.0035. A higher 0.0054 rate (effective 2026-06-08) applies to developer product, pass, subscription and private-server purchases by U.S. players who are age-verified 18+, in eligible games. Eligibility requires that player characters stay R15 (or a qualifying human-form or custom rig) for 100 percent of active playtime with no R6 option; set Studio Avatar Settings to R15 Only. Minimum cash-out 30,000 Earned Robux (114 USD), age 13+, W-8/W-9 on file. DevEx payouts are royalties since 2026-11-01: tax information lives at Creator Hub > Finances > Taxes; without a valid W-9/W-8, 24 percent backup withholding applies; one completed cash-out per calendar month (docs `tax-information`). **Roblox Wallet** (announced 2026-09-11): from Dec 2026 for US 18+ independent creators (invite, opt-in), daily USD payouts after a hold of up to 30 days at the DevEx rate; Roblox says it will transition away from DevEx in the US in mid-2027, other regions later. Do not plan a payout strategy on DevEx beyond mid-2027 (US). Direct purchases, monthly Premium/Plus grants, resale and Robux transfers do not count. Re-read `developer-exchange` before quoting rates to a user.

## 3. Analytics and live ops

- Creator Dashboard analytics: engagement, retention (D1/D7 and beyond), monetization, acquisition, performance, crashes, demographics; custom events, funnel events, economy events, custom dashboards and alerts.
- Economy events use Source/Sink with transaction types IAP, TimedReward, Onboarding, Shop, Gameplay, ContextualPurchase; funnels up to 10 x 100 steps. Configs: up to 1,000 active configs, 100 conditions; read with `ConfigService:GetConfigAsync`/`GetConfigForPlayerAsync`; publish takes 15-60 s. Experiments run 14-60 days, 2 variants plus control, metrics D1, D7, playtime, ARPU, ARPPU, payer conversion.
- Instrument before launch: onboarding funnel steps, first purchase, session length, quit points, economy sources and sinks.
- **Experiment guard rails (O):** Early Harm Detection watches the first 24 h and flags critical harm at -10% playtime, -20% ARPU or -20% payer conversion; it needs 10,000 enrolled users. A sample-ratio-mismatch (SRM) banner means stop and restart. Under about 1,000 DAU an experiment rarely reaches significance, so ship clear wins and watch the dashboard instead. `GetConfigAsync` does not apply experiment variants; use `GetConfigForPlayerAsync`.
- Creator Hub has benchmark sets (Similar experiences / Genre) and retention by acquisition source; benchmarks do not affect ranking. Do not compare play-through rate across 2026-10-12: a measurement change raised impressions and slightly lowered PTR (Roblox says RFY was unchanged).
- **Experiments** (A/B tests) and **Configs** (remote values) ship balance and UI changes safely. Open Cloud exposes both for automation (configs API is beta, experiments API experimental, so expect changes; configs publish is limited to 10 per minute).
- `RecommendationService` lets you build in-game recommendation carousels (register items, log one impression per item per session, log quality actions, fetch).
- Live ops plan: a content cadence, events (Experience Events), and a weekly review of retention, funnel and error reports. Write the **first 4 weeks** before launch: one repeatable drop type (weekly-to-monthly, built on existing systems), one timed event announced as an Experience Event, one limited item or restock; check it against the holiday calendar. Chart games update constantly: 35 of 37 with 20K+ players had updated within 7 days (M, 2026-11-03), and seasonal events with a pass can lift an evergreen game sharply (MM2 +146% Sep to Oct 2026, V).

## 4. Age, safety and content maturity (check before design is final)

- **Content maturity** is required: without it Roblox restricts playability for everyone. Fill the Maturity & Compliance questionnaire (Creator Dashboard > experience > Publish settings or Audience > Maturity & Compliance); answer for the most mature content a player can meet. Misrepresenting it risks moderation. It also asks whether the game sells paid random items or allows paid item trading, and whether it respects `ArePaidRandomItemsRestricted` and `IsPaidItemTradingAllowed`: answer from what the code does (docs `content-maturity`). A new universe needs its own questionnaire.
- Labels and who can play: **Minimal / Mild** reaches Roblox Kids (5-8) and Select (9-15); **Moderate** reaches Select (9-15) and standard (16+); **Content May Vary** needs age-checked 16+; **Restricted** needs age-verified 18+ (servers run restricted). Realistic or excessive violence, blood, crude humour or romance in uploaded assets can be moderated whatever the label.
- **16+ release path:** account in good standing and at least 2 days old, age check, and answer the first questionnaire question (answering No gives Content May Vary, 16+ only). A maximum of 5 first-time releases per day.
- **Simpler publish flow (since Oct 2026):** Studio File > Publish asks one question; a game with no age-restricted content answers No and reaches players 16+ (Content May Vary) in most regions instead of filling the full questionnaire (up to 30 questions). The full questionnaire is still needed for restricted content or Kids / Select reach. Audience is set in Creator Hub > Manage Audience (Playtest / Public); "Playtest" replaced Private and Limited (details: `roblox-release-automation` section 1). **Early testers:** invite up to 10 friends to preview an unpublished game in the Roblox app. Highly Engaged Player counts in Creator Hub update hourly.
- **Roblox Kids / Select (all ages):** age check plus facial age estimation or ID verification, 2-step verification, Plus/Premium for 2 consecutive months or a 1,000 Robux refundable fee (50,000 for expedited review), the full questionnaire with a Minimal/Mild/Moderate result, and an evaluation of 250 unique plays by highly engaged age-checked users within 60 days (docs, read 2026-11-02; "highly engaged" weighs account age, play history and spend; evaluated hourly, progress on the Creator Hub Audience Reach dashboard). A DevForum post (2026-09-11) says the entry bar drops to 100 in Nov 2026 and the maintenance bar is 25 since 2026-07-16: re-read the docs before quoting. Select-only publishing drops the fee/subscription requirement. Confirm the intended audience in `roblox-project-intake`.
- Free text between players (signs, boards, pet names, trading notes) outside `TextChatService` is enforced against now; see `roblox-engine-2026` section 5.
- Age checks (facial age estimation) gate chat and other features; do not build features that bypass `TextChatService` filtering. Platform-integrated chat becomes mandatory for all games in May 2027 (see `roblox-engine-2026` section 5), and voice chat is limited to experiences of 100 players or fewer. Custom Quick Words (live 2026-10-13): up to 3 categories of 3-10 phrases, each under 25 characters, English input, reviewed; set at Configure > Chat > Quick Words.
- **Generative AI in games:** Roblox-served AI (`GenerationService`, `TextGenerator`) is moderated and aims at All Ages; third-party AI output is your responsibility and must follow Community Standards. A game whose main purpose is continuous chat with an AI character, or whose AI remembers prior sessions, has "extended AI interactions": answer Yes in the questionnaire and expect a Restricted (18+) label. **Required disclosures (docs `generative-AI`):** at the start of any AI interaction and throughout the session, show a visible notice that the player is talking to AI (example: "This is an AI-powered conversation, not human. It may make mistakes."); direct players who seek medical or professional advice to authoritative resources, and when a player shows signs of self-harm or a mental health crisis, the AI must encourage them to seek support and point to crisis resources.
- Disclosures, IP and rights: follow the IP guidelines and Rights Manager; keep `assets/LICENSES.md`; do not publish copied art or music.

## 5. Pricing and balance changes

- Change one thing at a time and measure with an experiment, not a feeling (offline economy sims change price growth and per-tier gain together: section 1, 'Economy sim rules').
- Regional pricing is on by default for Robux subscriptions; plan prices accordingly.
- **Managed Pricing** (regional prices and price tests): new games and items are enrolled by default. Price tests need about 60,000 transactions per 30 days, so most new games cannot use them. It cannot fix prices hard-coded in UI (section 2, Plus row).
- Never raise prices on existing owners of a pass without a clear value add.

## 5b. Discovery (what the recommender rewards)

- Recommended for You retrieves then ranks; ranking counts only users who arrived through it. Strongest signals: play-through rate, first-play bounce rate (negative; 61-180 s window), play days per user (D1, D2-7, D8-28), playtime per user (capped at 60 min per user per game per day). Also: co-play days, qualified sessions, spend days, Robux spent per user. Signals are per-user averages, so small games are not penalised and new games need no 28-day wait.
- A custom thumbnail is required for home recommendations (in force since 2026-10-19: a default thumbnail gets no Home impressions). Metadata that does not match the content, giveaway-led titles and near-duplicate games hurt exposure.
- Description: the first about 160 characters matter most (common guidance, not found in the docs; about 1,000 total); hashtags and tags are not used.
- Other surfaces: Standout Games, Sponsored, semantic Search, Discover, notifications, experience events (max 10 events; update posts up to 60 characters, once every 3 days).
- Event surfaces (docs `experience-events`): **Trending Events in Experiences** lists a public event that started within 7 days and has 1,000+ RSVPs; **Off-Platform Featuring** (App Store, Google Play) needs the event submitted at least 7 days ahead; events running 7-30 days do best.
- **Moments** (newsroom 2026-07-28): a tab of player clips with a Join button, 16+ age-checked users only, rolling out from Canada, New Zealand and Singapore. Plan one clip-worthy moment (a big reveal, steal or win); in-game recording and share links (`CaptureService`, `SocialService:PromptLinkSharingAsync`) are in `roblox-fun-effects` section 6. Programs worth knowing: Creator Rewards, Developer Awards, Standout Games, Learn & Explore, Jumpstart (18+ novel games), Incubator.

## 6. Publish checklist

Who does what (agent vs user), API key scopes and missing-permission handling: `roblox-release-automation`. Benchmark gates: `roblox-launch-benchmarks`.

1. Dev place tested; a private test place built from the exact publish build; tester told what to check and the known issues.
2. Content maturity done; genre chosen; description honest (include controls, update notes; do not stuff keywords).
3. **Icon** 512x512 (previews scale down to about 150 px; check it small). **Thumbnails** 16:9, 1920x1080, under 3 MB; up to 10 images/videos; uploaded video has a monthly quota (3 uploads); YouTube video links were removed from game pages on 2026-09-30, so upload video files. Craft rules in `roblox-store-art-pack` section 5.
4. Localization: add source text, auto-translate or manual translations; check long strings in the UI (docs `production/localization`; accessibility: `production/publishing/accessibility`).
   - Source strings: a table entry matches a label's whole `Text` exactly and case-sensitively (docs `add-source-content`), so add the static literals players read (labels, names, descriptions, toasts). Automatic Text Capture can take up to a few days (docs); faster is Studio's Automatic Text Capture while playtesting (1-2 minutes, docs) or pushing the sources yourself: `scripts/l10n_sync.py` extracts literals from a Rojo src tree and adds only the missing ones (API in `roblox-release-automation` section 1). Pushed strings were auto-translated into every enabled language within minutes (one game, 2026-11). Runtime-built text: `roblox-ui-typography` section 7.
5. Accessibility (readable text, contrast, never colour or sound alone, honour `GuiService.PreferredTransparency`, `PreferredTextSize` and reduced motion); console (10-foot UI, TV-safe area, full controller navigation, no chat window); VR (OpenXR, default camera scripts, instance streaming, Quest aims for 72 fps); device and network simulator checks.
5b. Localization: source and supported languages, `AutoLocalize`, fonts that cover each language (`roblox-ui-typography` section 7); auto-translate covers 18 languages (Arabic, Chinese simplified/traditional, English, French, German, Hindi, Indonesian, Italian, Japanese, Korean, Polish, Portuguese, Russian, Spanish, Thai, Turkish, Vietnamese; the live list from English also had Dutch on 2026-11-04: `GET https://gameinternationalization.roblox.com/v1/automatic-translation/languages/en/target-languages`, no auth).
   - Source language first: it defaults to the creator account's language (docs), and text is assumed to be in it. A Korean-locale account with English strings got no translations at all (2026-11). Check with no auth: `GET https://gameinternationalization.roblox.com/v1/source-language/games/{universeId}`.
   - Settings (Creator Hub > Audience > Localization; docs `automatic-translations`): per supported language **Experience Strings & Products** on (**Experience Information** for the name and description); Settings tab: text capture from experience UI on and **Use Translated Content** on. Never press **Clear unmodified auto-captured entries**: it deletes those entries and their translations (docs `remove-content`).
   - Which languages: every one the auto-translation quota allows (initial and monthly, per character and per language, shown on the Languages tab). Rank by Creator Hub > Analytics > Demographics (country, top languages) and the target audience, not third-party country shares. Analytics: log events after success, not on attempt; custom events max 100 names; data rolls off after 90 days.
6. Assets owned by the publishing account/group and verified loadable in a live client.
6b. Group-gated rewards: the group must let outsiders join without manual approval, or no outside player can claim them. Check `publicEntryAllowed` on `GET /cloud/v2/groups/{id}`; changing it is a group-owner step, so list it in the hand-off.
7. Publish through Open Cloud (`versionType=Published`; `Saved` stages a version without releasing it); record the version number; keep the rollback version. The API skips EditableImage, EditableMesh, PartOperation, SurfaceAppearance and BaseWrap instances, so publish those places from Studio.
8. Day-1 watch: crashes, error reports, funnel drop-off, DataStore errors.

## 7. Account and rights hygiene

- Use a group-owned experience for teams; assets uploaded to the wrong owner render blank. Pick the owner before the first publish. A later move is the Creator Hub game ownership transfer (docs `projects/game-ownership-transfer`): ids and URL stay, but accepting closes all servers and takes the game off public until it is released again, and the group must first own the game's private ModuleScripts and InsertService assets. The page says nothing about passes, products, asset permissions or the questionnaire, so read each back after a move. One game that moved by recreating it on a new universe had to redo all of them (2026-11).
- Turn on 2-step verification; use API keys restricted to the one experience with the minimum scopes; keep keys in env files. IP allow-lists break keys used from Roblox servers, expiry dates need a rotation process, and keys unused for 60 days expire. Asset scopes follow the creator (user or group), so a user key cannot manage group assets without the group role.
- Create the game and its dev place separately; never edit the live place in Studio.
